**Автоматическая настройка SNI-сайта (маскировки) для Xray Reality: Nginx + Let's Encrypt**

Скрипт поднимает правдоподобный сайт-маскировку, получает для него настоящий TLS-сертификат и отдаёт его на внутреннем TLS-эндпоинте, на который Xray Reality направляет рукопожатие (`dest` / `target`).

## 🆕 Что нового в v2

- **Исправлен главный баг «не могу зайти на свой же сайт».** Причина была не в коде, а в архитектуре (см. [Как это работает](#-как-это-работает)). Теперь скрипт в конце **реально проверяет**, что сайт отвечает, и объясняет, почему напрямую в браузере он может не открываться.
- **Генератор уникальных сайтов** вместо случайной папки из публичной коллекции шаблонов. 15 тематик × случайная палитра, шрифты, орнамент и макет — каждый запуск даёт новый сайт, которого нет в индексах DPI.
- **Сертификат через `--webroot`**, а не `--standalone` — больше не нужно останавливать nginx, продление не роняет сайт.
- **Режим `direct`** — если хотите, чтобы nginx сам слушал `443` и сайт открывался напрямую в браузере (без Reality на 443).
- **Проверка DNS по A и AAAA**, несколько сервисов определения IP с фолбэком.
- **Понятные ошибки**: какой процесс занял порт, что именно не так с DNS, хвост лога при сбое.
- **Аргументы командной строки** и неинтерактивный режим (`-y`), команды `--check` и `--uninstall`.
- Корректная работа при запуске и через `bash <(curl ...)`, и через `curl | bash`.
- Условные `listen [::]` — не роняет nginx на серверах без IPv6.

## 🧠 Как это работает

Это важнее всего понять — именно непонимание схемы и порождает жалобу «сайт не открывается».

В связке с **Reality порт `443` слушает Xray, а не nginx.** Когда к серверу приходит TLS-рукопожатие с нужным SNI, Xray проксирует его на ваш сайт-маскировку, который nginx отдаёт **только на localhost** — `127.0.0.1:<порт>` (по умолчанию `9000`).

```
          клиент (браузер / Xray-клиент)
                      │  TLS, SNI = ваш домен
                      ▼
        ┌─────────────────────────────┐
        │  Xray на 0.0.0.0:443         │   ← порт 443 держит Xray
        │  (VLESS + Reality)           │
        └───────────────┬─────────────┘
                        │ dest / target = 127.0.0.1:9000
                        ▼
        ┌─────────────────────────────┐
        │  nginx на 127.0.0.1:9000 ssl │   ← только localhost!
        │  сайт-маскировка + сертификат│
        └─────────────────────────────┘
```

Отсюда следствие: **если открыть `https://ваш-домен` в обычном браузере, вы попадёте на Xray, а не на nginx-сайт.** Сайт виден только через сам механизм Reality. Это нормально и правильно — так и должно быть.

Если вам нужно, чтобы сайт открывался **напрямую в браузере** (например, домен без Reality на 443), используйте режим `direct` — тогда nginx сам займёт `443`:

```bash
bash fakesite.sh -d example.com -m direct
```

## 🚀 Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/begugla0/selfsniscripts/main/fakesite.sh)
```

или вручную:

```bash
wget https://raw.githubusercontent.com/begugla0/selfsniscripts/main/fakesite.sh
chmod +x fakesite.sh
./fakesite.sh
```

**Требования:** Debian 10+ / Ubuntu 20.04+, root, свободные порты 80 и 443, A-запись домена на IP сервера.

## ⚙️ Параметры командной строки

Скрипт можно запускать интерактивно (как раньше) или полностью из аргументов:

```bash
bash fakesite.sh -d de.example.com -p 9000 -t coffee -y
```

| Параметр | Назначение |
|---|---|
| `-d, --domain DOMAIN` | доменное имя |
| `-p, --port PORT` | внутренний порт nginx для Reality (по умолчанию 9000) |
| `-m, --mode MODE` | `reality` (по умолчанию) или `direct` |
| `-t, --template T` | `random`, конкретная тематика, `github`, `keep` или путь к своему сайту |
| `-e, --email EMAIL` | e-mail для Let's Encrypt (необязательно) |
| `--proxy-protocol` | nginx принимает PROXY protocol от Xray (нужен `xver: 1`) |
| `--skip-dns-check` | не сверять DNS (сервер за NAT и т.п.) |
| `-y, --yes` | без вопросов, значения по умолчанию |
| `--check` | диагностика: почему сайт не открывается |
| `--uninstall` | удалить сайт и конфиг |
| `--themes` | список тематик генератора |
| `-h, --help` | справка |

## 🎨 Разнообразие сайтов-масок

Раньше скрипт клонировал случайную папку из `learning-zone/website-templates` — одни и те же общеизвестные шаблоны, легко индексируемые.

v2 по умолчанию **генерирует сайт на лету**. Каждый запуск комбинирует:

- **тематику** — 15 вариантов (кофейня, архбюро, юрфирма, стоматология, фотостудия, разработка ПО, пекарня, логистика, бухгалтерия, йога, дизайн интерьеров, веломастерская, флорист, ремонт, бюро переводов);
- **палитру** — светлые и тёмные схемы;
- **пару шрифтов** Google Fonts;
- **SVG-орнамент**, макет (слева / по центру) и скругления.

Результат — каждый раз новый правдоподобный сайт с разделами (услуги/цены, «о нас», шаги работы, отзыв, контакты с часами работы), которого нет в публичных коллекциях.

```bash
bash fakesite.sh --themes            # список тематик
bash fakesite.sh -t law              # конкретная тематика
bash fakesite.sh -t random           # случайная (по умолчанию)
bash fakesite.sh -t github           # старое поведение — готовый шаблон с GitHub
bash fakesite.sh -t /root/mysite     # свой сайт (нужен index.html)
bash fakesite.sh -t keep             # оставить текущий сайт
```

## 🔌 Настройка Xray / 3x-ui / Marzban

После установки скрипт покажет параметры. Для **reality** укажите в инбаунде:

- **dest / target:** `127.0.0.1:9000` (ваш порт)
- **serverNames / SNI:** `ваш-домен`
- Xray слушает `443`.

Используйте **свой** сертификат Reality (Reality не требует файлов сертификата сайта — он берёт реальный сертификат домена «на лету»). Сам сайт-маскировка использует выписанный скриптом сертификат автоматически.

> Сертификаты, полученные скриптом, предназначены **только** для сайта-маскировки. Не используйте их для панелей (3x-ui, Marzban) — для панелей заведите отдельный домен и сертификат.

## 🩺 Диагностика: «сайт не открывается»

```bash
bash fakesite.sh --check -d ваш-домен
```

Команда проверит: есть ли конфиг и сертификат, запущен ли nginx, валиден ли конфиг, какой порт слушается, и **отвечает ли сайт на внутреннем TLS-эндпоинте** так же, как его увидит Xray. Если всё зелёное, а в браузере «сайта нет» — это ожидаемо для режима reality (см. [Как это работает](#-как-это-работает)).

## 🗑️ Удаление

Удалить сайт-маскировку можно двумя способами.

### Отдельный скрипт `remove.sh` (рекомендуется)

Запускается так же, как установщик — через `curl`, ничего заранее скачивать не нужно:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/begugla0/selfsniscripts/main/remove.sh)
```

Без аргументов скрипт **находит все установленные сайты-маски** (в том числе от старой версии) и предлагает выбрать, что удалить:

```
Найденные сайты-маски:

  1) de.example.com (есть сертификат)
  2) nl.example.com
  a) удалить все
  q) выйти

Что удалить? (номер / a / q):
```

Что делает скрипт: снимает symlink и конфиг nginx, удаляет файлы сайта из `/var/www/selfsni/<домен>`, по желанию удаляет сертификат Let's Encrypt, убирает hook автопродления и cron **только если не осталось других сайтов-масок**, проверяет `nginx -t` и перезагружает nginx. Чужие конфиги nginx и сайты он не трогает. Перед удалением сохраняет бэкап конфига в `/root/selfsni-backup`.

| Параметр | Назначение |
|---|---|
| `-d, --domain DOMAIN` | удалить конкретный домен |
| `--all` | удалить все сайты-маски, созданные скриптом |
| `--with-cert` | удалить также сертификат Let's Encrypt |
| `--keep-cert` | НЕ удалять сертификат (без него скрипт спросит) |
| `--no-backup` | не сохранять бэкап конфига |
| `-y, --yes` | без вопросов (нужен `-d` или `--all`) |
| `-h, --help` | справка |

Примеры:

```bash
bash remove.sh                               # интерактивно
bash remove.sh -d de.example.com             # один домен, про сертификат спросит
bash remove.sh -d de.example.com --with-cert -y
bash remove.sh --all --keep-cert -y          # снести все маски, сертификаты оставить
```

### Через флаг установщика

В основном скрипте то же самое доступно как `--uninstall`:

```bash
bash fakesite.sh --uninstall -d de.example.com
```

> Если вы меняете домен — не обязательно удалять старый вручную. Запустите установщик с новым доменом: `bash fakesite.sh -d новый.example.com`.

## ❓ FAQ

**Почему сайт не открывается в браузере по https?**
В режиме reality 443 держит Xray, а сайт живёт на `127.0.0.1:9000`. Снаружи напрямую он не виден — только через рукопожатие Reality. Нужен прямой доступ — используйте `-m direct`.

**Можно ли поставить свой сайт?**
Да: `-t /путь/к/сайту` (в папке должен быть `index.html`) или `-t keep`, чтобы не трогать уже лежащий сайт.

**Поддерживаются ли поддомены?**
Да. Рекомендуется отдельный поддомен на локацию: `de.example.com`, `nl.example.com` и т.д.

**Как часто продлевается сертификат?**
Автоматически (systemd timer или cron), с перезагрузкой nginx через deploy-hook. Ничего делать вручную не нужно.

**Как изменить порт после установки?**
Проще перезапустить `bash fakesite.sh -d домен -p новый_порт`. Либо вручную поправить `listen 127.0.0.1:<порт> ssl;` в `/etc/nginx/sites-available/selfsni-<домен>.conf`, затем `nginx -t && systemctl reload nginx`.

**Работает ли с Cloudflare?**
Для SNI-маскировки отключите проксирование (серое облако) у домена — иначе сертификат будет от Cloudflare и Reality может работать нестабильно.

**Где логи установки?**
`/tmp/sni_setup_*.log`. При ошибке скрипт сам показывает последние строки.

## 🔧 Решение проблем

**Порт 80 или 443 занят.** Скрипт покажет, какой процесс занял порт. Для получения сертификата нужен свободный `80`. Если на `443` у вас Xray — это нормально для режима reality; скрипт займёт только `127.0.0.1:<порт>`.

**A-запись не совпадает с IP.** Проверьте `dig +short A ваш-домен`, подождите обновления DNS, при Cloudflare отключите оранжевое облако. Сервер за NAT — добавьте `--skip-dns-check`.

**Не удалось получить сертификат.** Откройте порт 80 (`ufw allow 80/tcp`), проверьте A- и **AAAA**-записи (лишняя AAAA — частая причина), помните про лимит Let's Encrypt (5 сертификатов на домен в неделю). Полный лог — в `/tmp/sni_setup_*.log`.

**Удалить всё.** `bash remove.sh` (интерактивно) либо `bash fakesite.sh --uninstall -d ваш-домен`. Сертификат удаляется по желанию, бэкап конфига — в `/root/selfsni-backup`. Подробнее — в разделе [Удаление](#-удаление).
